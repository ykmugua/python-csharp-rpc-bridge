# Python 业务模块接入 C# 的需求说明

## 1. 文档目的

本文定义项目范围、接口约束、运行行为和验收要求。功能说明以仓库当前实现为基础；当前未纳入自动化验收的能力会明确标注。

## 2. 项目目标

项目提供构建期工具和运行期组件，让 C# 应用通过独立 Python 进程调用受约束的 Python 业务模块。构建工具扫描 Python AST，生成 RPC 服务端、接口元数据和 C# 调用门面；C# Runtime 通过标准输入/输出上的 JSON 协议访问后端。

目标包括：

1. 允许 Python 开发者实现可扫描的业务函数及有状态类。
2. 在构建期校验接口，并生成 RPC 服务端和 C# API。
3. 通过源码哈希握手检测 DLL 与 Python 后端是否匹配。
4. 提供可重复生成、可测试并可纳入 CI 的流程。

## 3. 范围

### 3.1 包含

- Python 源码 AST 扫描、接口提取和源码哈希计算。
- 元数据、Python RPC 服务端和 C# Runtime/门面生成。
- C# 后端进程启动、请求响应分发、超时及生命周期管理。
- Python 测试、示例业务模块、可选 C# 示例及 CI。
- 可选的 Nuitka 独立后端打包入口。

### 3.2 不包含

- 操作系统级安全沙箱、权限隔离和 CPU/内存配额。
- 网络 RPC、跨机器调用、身份认证或传输加密。
- 自动生成业务逻辑、数据模型或数据库访问代码。
- 对所有 Python 版本、操作系统及任意第三方依赖的兼容保证。

AST 检查只约束部分源代码结构，**不构成安全边界**。不得将不可信 Python 代码直接作为安全隔离方案使用。

## 4. 用户与典型流程

| 用户 | 主要需求 |
|---|---|
| Python 业务开发者 | 编写业务函数或状态类，了解支持的语法和类型 |
| C# 应用开发者 | 使用生成的强类型门面访问 Python 能力 |
| 构建/发布维护者 | 生成、测试、打包并部署 DLL 与后端 |

典型流程：在 `modules/` 编写 `<模块名>.py` → 扫描并生成接口文件 → 构建 C# DLL 和后端 → 部署匹配文件 → Runtime 启动后端并校验哈希 → 应用通过生成 API 调用业务逻辑。

## 5. 功能需求

### 5.1 Python 接口扫描

1. 扫描器解析业务模块 AST，不导入并执行该模块来发现接口。
2. 模块顶层允许导入、函数、类和文档字符串；模块级赋值和可执行语句应被拒绝。
3. 函数参数和返回值使用 `int`、`float`、`str`、`bool`、`list`、`dict` 或 `None` 类型注解。
4. 函数不使用装饰器、仅位置参数、`*args` 或 `**kwargs`；参数默认值为标量字面值。
5. 类为普通类，不使用继承、元类和类装饰器；仅允许构造函数与实例方法。构造参数只支持 `int`、`float`、`str`、`bool`。
6. 实例方法文档字符串标明状态读写意图；`__del__`、`close` 和其他不支持的双下划线方法应被拒绝。
7. 异步方法、异步等待、`global`/`nonlocal` 及部分线程、套接字和显式资源创建写法应被拒绝。
8. 无效接口导致构建失败，并给出源码位置或明确原因。
9. 业务源码的 SHA-256 写入元数据，供运行时校验。

### 5.2 构建和命名

1. Windows 交互式入口 `modules/build.bat` 列出 `modules/` 顶层的 `.py` 文件，让用户选择源文件及 Release/Debug 配置。
2. 输入 `<模块名>.py` 的模块名取自文件基名；例如 `sample.py` 生成 `sample.dll`、`sample_rpc_server.py` 和 `sample_rpc.exe`。
3. 每个输入文件的生成及构建输出存入同级的 `modules/<模块名>/`，避免把生成物与业务源码混放。
4. `generated/python/` 存放元数据、业务源码副本及 RPC 服务端；`generated/csharp/` 存放 C# Runtime 和门面；`out/net48/release/` 与 `out/net48/debug/` 分别存放对应配置的 DLL、后端及运行依赖。
5. Release 通过 Nuitka 生成独立后端；Debug 不调用 Nuitka，由 Runtime 使用 Python 启动 RPC 服务端脚本。
6. `SOURCE_DATE_EPOCH` 被设置时，元数据构建时间由该值确定，以支持可重复生成。
7. 生成物由工具更新，不应手工修改；CI 检查提交的生成物是否与业务源码一致。
8. 一键构建只生成模块 DLL 和后端；`examples/csharp/` 的 C# 示例为可选源码，不自动生成示例构建输出目录。

### 5.3 RPC 协议和 Python 服务端

1. 每帧由 4 字节无符号小端序长度头和 UTF-8 JSON 组成，最大长度为 64 MiB。
2. 请求至少包含 `id`、`method`、`params`；响应通过相同 `id` 返回 `result` 或 `error`。
3. Python 服务端顺序处理请求；函数按名称分发，实例方法根据实例 ID 分发到对应实例。
4. 服务端提供 `__ping` 哈希握手和 `__instance` 类初始化入口。
5. 业务标准输出重定向到标准错误，避免污染 RPC 协议流。
6. Python 异常转换为 RPC 错误响应，包含错误类型、消息和可用 traceback。

### 5.4 C# Runtime 和 API

1. 每个模块提供进程级静态 Runtime，管理共享 Python 后端，并提供启动、停止和重启入口。
2. 启动时执行 `__ping` 并核对源码哈希；校验失败时停止后端并报告错误。
3. Runtime 重启会清除后端实例；旧实例代理不可继续使用。
4. C# 客户端支持并发调用，并使用请求 ID 将响应分发给对应调用方。
5. 写入失败、后端退出、无效响应和超时必须以明确错误暴露。
6. 后端在默认 60 秒窗口内崩溃 3 次时，重启熔断器阻止继续启动。
7. 可通过 `PYF_BACKEND_DIR` 和构建元数据定位后端。
8. 对只有一个 `str` 参数的方法，生成面向业务字符串的 C# 入口；原始 JSON 参数入口使用 `_json` 后缀。
9. Python 类映射为 C# 代理类，静态 `Create(...)` 工厂创建后端实例；多个代理对应独立状态，释放代理会销毁对应后端实例。

## 6. 非功能需求

- **可维护性：** 扫描和生成逻辑集中在 Python 包内，生成代码不与手写实现混淆。
- **可诊断性：** 构建错误包含源码位置或明确原因；运行错误带有错误类型和必要诊断信息。
- **可重复性：** 固定 `SOURCE_DATE_EPOCH` 后，相同输入生成相同文件。
- **生命周期：** C# Runtime 能停止并释放后端进程及相关流。
- **兼容性基线：** Python `>=3.14`；桥接库目标框架为 .NET Framework 4.8。
- **API 文档：** C# DLL 随附 XML 文档；生成业务函数带有简要功能说明。
- **程序集命名：** 一键构建使用 Python 源文件基名作为程序集名，例如 `sample.py` 输出 `sample.dll`。
- **可测试性：** 扫描器、生成器及 RPC 服务端由自动化测试覆盖；CI 运行 Python 测试、生成物检查和桥接库构建。

## 7. 验收标准

1. `uv run python -m python_csharp_rpc_bridge.build_tools.build` 能为示例模块生成元数据、Python RPC 服务端和 C# 门面。
2. 不支持的源代码结构导致构建失败，并给出可读错误。
3. RPC 服务端测试覆盖 ping、函数调用、类初始化、实例方法调用和错误响应。
4. Python 测试通过；生成的 Python 源文件可编译。
5. .NET Framework 4.8 桥接 DLL 构建成功。
6. 固定 `SOURCE_DATE_EPOCH` 后重复生成，生成文件字节一致。
7. C# 示例源码展示函数调用及多个独立类实例；端到端运行需先构建对应模块并部署匹配的后端。该示例不属于当前 CI 自动构建。

## 8. 当前仓库布局与状态

```text
src/python_csharp_rpc_bridge/ Python 包、扫描器和生成器
src/csharp/            C# 桥接库和 RPC Runtime
modules/               Python 模块源码、交互式构建入口及模块输出
examples/csharp/       可选 C# 示例源码
tests/                 自动化测试
toolchain/             本地 Zig 工具链目录
```

CI 执行 Python 测试、默认示例模块生成一致性检查及 .NET Framework 4.8 桥接 DLL 构建。CI 不运行 Nuitka，也不编译可选 C# 示例。构建和目录说明见[项目介绍](./项目介绍.md)。

## 9. 示例接口

`modules/sample.py` 提供：

- `add(a: int, b: int) -> int`：整数加法。
- `TextProcessor`：每个实例分别保存配置和调用状态，供多实例调用示例使用。
