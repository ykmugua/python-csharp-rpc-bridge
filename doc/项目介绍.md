# Python 到 C# RPC 桥接项目介绍

## 项目用途

本项目让 C# 应用通过独立进程调用 Python 业务逻辑。构建期工具使用 AST 扫描 Python 接口并生成：

- `meta.json`：接口信息及业务源码 SHA-256。
- `<模块名>.py` 和 `<模块名>_rpc_server.py`：规范化的业务源码副本及 RPC 服务端。
- C# Runtime、函数门面和类实例代理。

运行时通过标准输入/输出传输长度前缀 JSON。每帧由 4 字节无符号小端长度和 UTF-8 JSON 组成，最大 64 MiB。C# 根据请求 ID 分发并发调用的响应；Python 服务端在单个进程中顺序处理请求。启动时 Runtime 会通过 `__ping` 校验后端源码哈希。

## 仓库布局

```text
.
├── src/
│   ├── python_csharp_rpc_bridge/ Python 包、AST 扫描器、代码生成器
│   └── csharp/                  C# 桥接库和 RPC Runtime
├── modules/
│   ├── build.bat                Windows 交互式构建入口
│   ├── sample.py                示例 Python 业务模块
│   └── sample/                  sample 模块的构建目录
│       ├── generated/
│       │   ├── python/          元数据、RPC 服务端、业务源码副本
│       │   └── csharp/          生成的 Runtime 和业务门面
│       └── out/net48/
│           ├── release/         Release DLL、后端和部署依赖
│           └── debug/           Debug DLL、Python 脚本和部署依赖
├── examples/csharp/             可选 C# 调用示例，不由一键构建编译
├── tests/                       自动化测试和测试 fixture
├── toolchain/                   本地 Zig 工具链目录
├── doc/                         项目文档
│   ├── 项目介绍.md              本文
│   └── 需求说明.md              功能范围和验收要求
└── README.md                    快速开始
```

### 命名规则

- `modules/` 存放可被选择构建的顶层 Python 文件；构建入口与这些文件同级。
- 输入文件基名就是 Python 模块名和 C# 程序集名。例如 `sample.py` 对应 `sample.dll`。
- 每个模块的输出单独放入 `modules/<模块名>/`，避免生成物与业务源码混放。
- RPC 服务端和独立后端分别使用 `<模块名>_rpc_server.py`、`<模块名>_rpc.exe`。
- 生成的 C# 类型使用 PascalCase，例如 `sample.py` 对应 `SampleRuntime` 和 `SampleFunctions`；共享 C# 命名空间仍为 `ModulePlatform`。
- `examples/csharp/` 只包含可选示例源码，不是构建产物目录。构建脚本不会生成 `out/example/`。

这些约定避免重复的示例目录名，并把业务输入、自动生成代码、部署输出和可选示例分开放置。

## 环境与测试

- Python 3.14 或更高版本（`pyproject.toml` 声明 `>=3.14`）
- `uv`
- .NET SDK 8，用于构建目标为 .NET Framework 4.8 的桥接库
- Release 独立打包需要 Nuitka；Windows 一键构建还需要 Zig

在仓库根目录执行：

```powershell
uv sync --locked
uv run --locked python -m pytest -q
$env:SOURCE_DATE_EPOCH = "0"
uv run python -m python_csharp_rpc_bridge.build_tools.build
$backend = Join-Path (Get-Location).Path 'modules\sample\out\net48\release'
dotnet build src\csharp\ModulePlatform.csproj -c Release -o $backend -p:PyfModuleName=sample -p:PyfBackendDir="$backend"
Copy-Item modules\sample\generated\python\*.py $backend
```

构建 Python 模块后，桥接项目默认从 `modules/sample/generated/csharp/` 包含生成的 C# 文件。部署时还要将生成的 Python 文件或 Release 后端可执行文件放入后端目录。CI 执行 Python 测试、生成物检查和桥接 DLL 构建，不编译可选 C# 示例。

## 一键构建

在 Windows 上运行：

```powershell
.\modules\build.bat
```

脚本列出 `modules/` 顶层的 `.py` 文件供选择，再选择 Release 或 Debug。选中 `<模块名>.py` 后，目录如下：

```text
modules/
├── <模块名>.py
└── <模块名>/
    ├── generated/
    │   ├── python/
    │   └── csharp/
    └── out/net48/
        ├── release/
        └── debug/
```

Release 使用 Nuitka 生成独立后端，并将 DLL 与运行所需文件放入 `out/net48/release/`；Debug 跳过 Nuitka，Runtime 通过 Python 启动 RPC 脚本，输出到 `out/net48/debug/`。两种配置都生成以输入文件基名命名的 DLL。构建入口不会编译 `examples/csharp/`。

Release 使用 Zig 的步骤和放置规则见[工具链说明](../toolchain/README.md)。

## 手动添加模块

把 `<模块名>.py` 放入 `modules/`。文件名必须是有效 Python 标识符。为接口添加支持的类型注解后，在仓库根目录执行：

```powershell
uv run python -m python_csharp_rpc_bridge.build_tools.build --source-file modules\my_module.py --output-root modules\my_module
$generated = Join-Path (Get-Location).Path 'modules\my_module\generated\csharp'
$backend = Join-Path (Get-Location).Path 'modules\my_module\out\net48\release'
dotnet build src\csharp\ModulePlatform.csproj -c Release -o $backend -p:PyfModuleName=my_module -p:PyfGeneratedDir="$generated" -p:PyfBackendDir="$backend"
Copy-Item modules\my_module\generated\python\*.py $backend
```

生成器要求 `--source-file` 与 `--output-root` 同时提供。该调用生成 `modules/my_module/generated/python/` 和 `modules/my_module/generated/csharp/`；示例命令将 Python RPC 脚本和业务副本复制到后端目录。Release 独立发布时还需使用 Nuitka 生成并部署 `<模块名>_rpc.exe`。

## Python 接口约束

扫描器允许的注解为 `int`、`float`、`str`、`bool`、`list`、`dict` 和 `None`。构造函数参数限于 `int`、`float`、`str`、`bool`，默认值必须为标量字面值。当前不支持装饰器、继承、元类、异步函数、仅位置参数、变长参数、模块级赋值和类变量等结构。实例方法的文档字符串需要说明其状态读写意图。

扫描器会拒绝部分线程、套接字、异步和显式文件资源相关写法，但它不是安全沙箱，不能保证业务代码无副作用。运行不可信代码时，应由操作系统或容器提供隔离。

当方法只有一个 `str` 参数时，生成的 C# API 使用业务字符串入口，并保留 `_json` 后缀的原始 JSON 参数入口以避免 CLR 签名冲突。

## C# 调用示例

[示例业务模块](./modules/sample.py)含有 `add` 和带状态的 `TextProcessor`。[C# 示例源码](./examples/csharp/Program.cs)展示普通函数调用和创建两个独立实例。先生成并构建 `sample` 模块，再在 `examples/csharp/` 编译可选程序：

```powershell
dotnet build examples\csharp\SampleExample.csproj -c Release
.\examples\csharp\bin\Release\net48\SampleExample.exe
```

示例项目默认从 `modules/sample/out/net48/release/` 加载 DLL 和后端文件。可通过 MSBuild 属性 `PyfOutputDir` 与 `PyfModuleName` 指定其他模块。此示例不会由 `modules/build.bat` 或 CI 自动编译。

成功运行时会输出 `add(20, 22) = 42`，并展示法语和德语两个 `TextProcessor` 实例各自独立的状态。

## 运行时行为

- 每个生成模块提供进程级静态 Runtime；函数门面共享该 Runtime 管理的客户端。
- Python 进程顺序执行请求；长时间运行的函数会阻塞后续请求。
- C# 默认调用超时为 30 秒；后端在默认 60 秒窗口内崩溃 3 次会触发重启熔断。
- 每个类代理代表一个独立的 Python 对象；释放代理会请求销毁对应实例。
- 可通过 `PYF_BACKEND_DIR` 覆盖后端目录。修改业务源码后必须重新生成，并部署相匹配的 DLL 与后端。
